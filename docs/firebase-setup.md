# Firebase の準備

共有に使うのは Authentication（Google）と Firestore だけです。Spark（無料）プランで足ります。Hosting は今までどおり GitHub Pages です。

`src/firebase-config.ts` には、ブラウザに載せてよい Web 設定が入っています。秘密鍵ではありません。ルールを本番に入れるまでは、サイトは「まだ準備中です」と出します。テストと E2E は `VITE_FORCE_LOCAL=1` でビルドし、共有にはつながりません。

## 1. プロジェクトを作る

1. [Firebase コンソール](https://console.firebase.google.com/) でプロジェクトを作る。
2. プロジェクトの設定 → マイアプリ → ウェブアプリを追加する。
3. 表示された `apiKey`、`authDomain`、`projectId`、`appId` を `src/firebase-config.ts` の `firebaseConfig` に入れる。この4つはブラウザに載る値で、秘密鍵ではありません。
4. Authentication → ログイン方法 → Google を有効にする。
5. Authentication → 設定 → 承認済みドメインに `chihironishioka.github.io` を足す。`https://` や `/dajare-vault/` は付けません。動作確認用の `localhost` も足します。

ログインはポップアップだけです。失敗してもリダイレクトには切り替えません。iPhone の Safari では、ログインを押した瞬間にポップアップを開く必要があります。ページを開いたときに認証の準備を始めるので、ボタンを押してから読み込みを待たないでください。ポップアップが止められたときは「もう一度タップ」と出ます。そのときは、もう一度ログインを押してください。

## 2. 編集者を足す

編集できる人は、Firestore の `editors` コレクションにドキュメントを1つ足すだけで増えます。ルールの書き換えは要りません。

1. Firestore を本番モードで作る（ルールは次の節でリポジトリの `firestore.rules` を入れます）。
2. コレクション `editors` を作る。
3. ドキュメント ID は、その人の Google アカウントのメールアドレスを**小文字**にしたもの。
4. フィールド `publicName` に、紙の上に出す名前を入れる（1〜40文字。例: `ママ`）。駄洒落の文書に残るのはこの名前と uid だけです。メールアドレスは入れません。
5. Google の表示名は使いません。ルールが、書いた人の名前と `publicName` の一致を見ます。

最初に入れる人のアドレスは、コンソールだけで足してください。ルールファイルやこの説明には書いていません。

本人以外は、誰が編集者かを一覧できません。自分のドキュメントを読めるかどうかだけが、編集者かどうかの判定です。Google 以外のログインや、メール未確認では編集できません。

## 3. ルールを入れる

リポジトリ直下の `firestore.rules` が正です。コンソールに貼っても、CLI でも同じです。

```bash
npx firebase login
npx firebase deploy --only firestore:rules --project <プロジェクトID>
```

初回は `firebase init firestore` で既存の `firestore.rules` を選んでください。ファイルを上書きしないこと。

ルールのテストは、Java の入った環境で次を実行します。CI も同じです。

```bash
npm run test:rules
```

## 4. 紙を共有DBへ移す

設定を入れてサイトを開くと、Google でログインできます。`editors` に入り、`publicName` がある人だけ、追加・編集・削除が出ます。

共有DBに「初期データの移行が終わった」印（`meta/seedMigration`）が無いあいだ、編集者には「初期データを共有DBに入れる」が出ます。紙が1件もないときだけ、ではありません。途中で止まったときは、同じボタンで続きから入れられます。

1件ずつ、まだ無い id だけを作ります。すでにある紙は上書きしません。全部見終わったら印を付けます。印は作るだけで、変更も削除もできません。印のあとで誰かが初期データを消しても、ボタンは出ず、消した紙は戻りません。

共有モードでは、空の端末に見本を自動では保存しません。「この端末のデータを共有DBへ送る」は、その端末で自分で足した紙があるときだけ出ます。送る前に、新しく送る件数、すでに同じIDがある件数、中身が違うので飛ばす件数、共有DBに無い見本の件数を出します。見本の id は、印があるあいだは送り直しません。

削除の前にも確認を出します。JSON の書き出しは、ログインしていなくてもできます。読み込みは編集者だけです。

## 5. バックアップ

Spark（無料）プランには、Firestore の自動バックアップも、ポイントインタイムリカバリもありません。消した紙はデータベースからは戻りません。

定期的に画面の「保管」から JSON を書き出して、ファイルとして残してください。それがこのプランでのバックアップです。
